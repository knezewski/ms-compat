# Проверка совместимости с JavaScript

Из корня проекта:

```sh
cargo test --locked --test js_compat -- --ignored --nocapture
```

Нужен Node.js; npm-пакеты и сеть при запуске не используются. Если `node`
отсутствует в `PATH`, укажите путь к исполняемому файлу через переменную `NODE`.
Обычный `cargo test` пропускает этот тест, чтобы библиотеку можно было проверять
без JavaScript runtime. В CI сравнение нужно запускать отдельной командой выше.

Тест сравнивает публичные Rust-функции с JS-оригиналом на 100 793 числовых входах
в обоих форматах и 20 017 строках. Корпус генерируется SplitMix64 с постоянным
seed `20261110`; генератор не зависит от сторонних библиотек. Он включает
случайные битовые представления `f64`, соседние значения около границ единиц
и округления, экспоненциальную запись, оба знака нуля, NaN, бесконечности,
допустимые и ошибочные строки, Unicode и границы длины UTF-16.

Числа передаются как 16 шестнадцатеричных цифр IEEE 754, строки — как UTF-8
в hex. Это сохраняет отрицательный ноль и исключает искажения JSON-конвертации.
Форматирование сравнивается посимвольно, результат парсинга — побитово.
Исключение JS для неверной длины сопоставляется с `InvalidLength`, `NaN`
при неверном формате — с `InvalidFormat`, отказ форматировать NaN/Infinity —
с `NotFinite`. Неожиданное исключение JS завершает тест с ошибкой.
При расхождении выводятся seed, индекс случая, вход в hex и оба результата.

## Версия эталона

`ms-original.cjs` содержит константы и функции `parse`, `fmtShort`, `fmtLong`,
`format`, `plural` из [`vercel/ms`, commit
`4ff48cec099f0514c3e9bbca18706c9c21122bfb`](https://github.com/vercel/ms/blob/4ff48cec099f0514c3e9bbca18706c9c21122bfb/src/index.ts).
Удалены TypeScript-аннотации, приведения типов и неиспользуемые экспорты;
добавлен CommonJS-экспорт `parse` и `format`. Исполняемая логика сохранена.
MIT-лицензия оригинала находится в `LICENSE.ms`.

Эталон зафиксирован в репозитории и не загружается с `main` во время теста.
При обновлении выберите конкретный SHA, перенесите функции из этой версии
с удалением только типов и обновите ссылку и лицензию. Изменения эталона следует
проверять по исходнику upstream, сохраняя его независимым от Rust-реализации.
